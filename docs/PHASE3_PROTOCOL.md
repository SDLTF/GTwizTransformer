# Phase-3 protocol: formal GraphGPS and remote structural attacks

This protocol is frozen before any Cora or CiteSeer Phase-3 run is generated.
Engineering smoke tests use only synthetic SBM graphs and cannot change the
methods or decision thresholds below.

## Architecture

Phase 3 replaces the custom dense-transformer proxy with a traceable subclass
of PyTorch Geometric 2.8 `GPSConv`. The model follows the GraphGPS recipe:

1. random-walk structural encoding (RWSE) is embedded with node features;
2. a GIN message-passing branch processes observed graph edges;
3. global multi-head self-attention processes every node;
4. the local and global residual branches are summed and passed through the
   GPS feed-forward block.

The traceable subclass preserves the installed `GPSConv` forward equations.
In trace mode only, PyTorch multi-head attention is asked to return per-head
attention weights, and its projected value tensor is retained. A unit test
must show that traced and non-traced logits agree.

Canonical model configuration:

- induced graph size: 192 nodes;
- hidden width: 96;
- RWSE length: 8, projected to 16 channels;
- four GPS layers and eight attention heads;
- local operator: GIN;
- global operator: exact PyTorch multi-head attention;
- datasets: Cora and CiteSeer;
- untouched seeds: 4510, 4511, and 4512.

This phase validates GraphGPS only. It does not establish a Graphormer result.

## GPU execution contract

Attack candidates and counterfactual removals are evaluated as batches of up
to 64 complete graphs. Their dense adjacencies and RWSE powers are recomputed
on GPU before one batched GraphGPS forward pass. The implementation records
CUDA peak allocated/reserved memory, graph-batch size, and wall-clock timing.
Out-of-memory fallback may reduce batch size, but may not change candidate
sets, scores, seeds, or statistical units.

## Threat models

Both attacks are untargeted evasion attacks against a known target node. The
attacker maximizes cross-entropy for the target's true class and adds edges
greedily, recomputing RWSE and model outputs after every addition.

- `incident`: every added edge is incident to the target node.
- `remote`: neither endpoint may equal the target. One endpoint must be a
  current one-hop neighbor of the target, so the new edge can affect the local
  branch within the next GPS layer. This is a non-incident, two-hop structural
  attack, not an arbitrary disconnected-graph attack.

Candidate construction may use current predictions, current graph structure,
features, and the target identity. Candidate-node true labels are forbidden.
Budgets are B in {1, 2, 4, 8}; six correctly classified boundary-near targets
are attacked per model with a pool of up to 64 candidate edges per greedy step.

## Localization inputs and generators

As in earlier phases, deployable localization receives only the graph presented
at inference, the known target, its current predicted class, current layer
traces, and Gaussian distribution parameters fitted on clean edge traces. It
does not receive the paired clean graph, graph difference, true attack edges,
or target true label.

Candidate sets have K=10B and are generated by:

- `all_layer`: global all-layer full-channel anomaly ranking;
- `temporal_residual`: global inter-layer residual ranking;
- `global_union`: deterministic round-robin union of the preceding two;
- `target_incident`: target-incident edges first, retained as a structural
  prior/control. It is not part of the primary remote-attack method.

Every shortlisted edge is removed counterfactually. The primary deployable
reranker is the Phase-2 holdout winner, `hybrid_label_free`: robust-z base
anomaly plus robust-z drop in the current predicted-class probability. Pure
predicted-class drop and a true-label margin oracle are secondary.

## Predeclared questions and decisions

Only successful attack snapshots enter localization metrics. Nested budgets
are clustered by dataset/seed/attack-type/target.

### A. Remote attack viability

Remote viability is supported if at least 12 model-target clusters across at
least two seeds contain a successful remote attack. Otherwise remote
localization is declared underpowered regardless of ranking metrics.

### B. Formal-GraphGPS dynamics fingerprint

On successful remote attacks, all-layer anomaly must improve both AUPRC and
Recall@B over a deterministic random ranking with cluster-bootstrap 95%
confidence-interval lower bounds above zero.

### C. Label-free causal localization

On successful remote attacks, `global_union + hybrid_label_free` must improve
both Recall@B and unnormalized repaired true-margin gain over the all-layer
anomaly baseline with 95% lower bounds above zero. Unnormalized margin is
primary because Phase 2 showed that recovery ratios become unstable when the
clean-to-attacked margin denominator is near zero. Normalized recovery and
repair-restoration rate remain reported secondary endpoints.

### D. Incident-prior separation

Incident and remote results are reported separately. `target_incident` is
expected to help incident attacks and serves as a negative/control prior for
remote attacks. No aggregate result may mix the two threat models into a main
claim.

## Interpretation gate

A positive Phase 3 supports the existence of a layer-wise localization signal
in a standard GraphGPS architecture under the specified attack. It does not
support architecture-independent localization, certification, or fully remote
subgraph detection. Certificate experiments remain a later phase.
